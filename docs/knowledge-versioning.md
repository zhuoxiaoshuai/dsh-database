# 经验库版本、草稿和发布边界

## SQL 版本链

`familyId` 表示同一模板家族；`lineageId` 表示该家族内的一条独立版本链。`variant` 是展示名称，可以重复，不用于判定版本归属。

- `create` 建立新家族和新版本链，从 v1 开始；相同正文的去重仅针对当前已发布版本。
- `newVersion` 保留家族和版本链，版本递增。
- `variant` 保留家族，建立新的版本链，从 v1 开始。
- 检索、相似分析和整理审批共用版本链边界。最新版本按版本号选择，使用次数和更新时间不能使旧版本重新成为最新版本。
- 链头从完整已发布历史中判定，不能先过滤归档记录。新版本号按完整历史递增；最高版本已归档时整条链关闭，旧版本不能重新成为可续写模板。
- `newVersion`、`variant`、`mergeMeta`、`useExisting` 在 Provider 和实际 Store 提交边界检查目标连接及数据源。异步解析后重新读取并检查目标。无连接归属的旧模板不能通过发布请求认领。

普通编辑器提交加载时保存的 ID、版本和内容快照。相似分析返回目标的内容快照，相似发布按钮原样携带它。元数据审批不必增加正文版本，但内容快照仍能检测它；检索刷新不能更新编辑器的保存基线。

SQL 首次保存先持久化，再异步分析。发布 API 等待本次保存自己的分析补全后返回最终内容；补全发现其他作者已经修改元数据时，不把该修改算作本次保存的确认，也不覆盖对方的元数据。底层 Store 的直接创建接口仍可在分析完成前返回。

## 归档

删除当前 SQL 链头会在一次提交中归档整条版本链，历史 ID、版本及正文保留，同家族的其他变体不变。普通删除、重复项归档及整理审批共用整链归档规则；不能归档保留项所在的链。旧页面对旧链头的操作拒绝，不能删除后来出现的新版本。归档后可以把保留的编辑内容另存为新模板。

`template-archive` 必须提交 `id`、`connectionId`、`expectedVersion`；Provider 提供当前方言，Store 再校验连接、方言及链头。成功返回 `{ ok: true, archived: string[] }`，其中 `archived` 包含该链全部条目 ID，供客户端标记关联草稿。旧调用缺少版本会收到明确错误，不执行删除。

历史文件中最高版本已归档、祖先仍未归档的链也不再显示。已有同链重复版本不自动重编号或删除，读取时标记为关系不明确，未归档内容仍可查看、另存，禁止原地续写。读取不改写原文件，存储格式保持 v3。

## 旧文件兼容

读取支持 `sql-templates.json` v1、`knowledge.json` v2 和 v3；新写入使用 v3。

旧 SQL 记录按连接、方言和家族分组，结合存储顺序、变体标识和版本前驱恢复版本链。只有唯一前驱且前驱尚无后继时才接续。无法确定的整组记录保留各条内容，并标记 `lineageAmbiguous`；界面允许阅读及另存新模板，不允许续写或合并它们的历史。它们不参与新建时的自动去重。

首次升级写入前，原文件以独占方式备份为 `knowledge.json.v1.bak` 或 `knowledge.json.v2.bak`。已有备份与原文件内容不同则拒绝升级，保留原文件和当前内存状态。读取本身不改写文件。

旧版程序不能读取 v3。需要回退程序时，应在停止相关进程后恢复升级前的备份；升级后的新增内容需要另行保留。

## 编辑会话

草稿身份、逐字段编辑修订和已确认基线由四种数据源共用的会话模块维护。MySQL、Oracle、Redis、Kafka 保存期间可继续编辑；成功回执只推进所属草稿的基线，未改动字段接收规范化结果，继续修改的字段保留当前输入。字段修改后即使改回原值，也按发生过编辑处理。失败不推进基线、不自动重试。

会话按草稿身份保存唯一内容，条目 ID 仅绑定选中的草稿。切走再返回恢复原会话，保存生成新 ID 后同步更新关联；普通保存与相似模板发布使用同一个回执合并函数。目标条目已有另一份草稿时两份都保留，不替换当前编辑缓存；保留的草稿提供按标题恢复的入口。每次点击新建都产生新身份，即使从已有条目进入也不复用早先的新建草稿；旧输入可通过恢复入口找回。未保存修改、保存请求、在途执行、执行快照任一存在都保留原稿；没有这些保留原因、引用或恢复标记的旧会话会释放。执行结束只解除在途状态，成功、失败、取消、unknown 和无结果集终态均保留快照。

普通重选、搜索与审批刷新不会用最新列表替换已有执行记录的草稿，也不会推进保存基线。列表条目有更新时提示重新加载；没有修改、请求或执行记录的干净缓存仍按现有规则更新。SQL 与命令会话共用 DraftSession.executionSnapshot 和 shouldRetainDraft，来源结果及错误继续分别保存。

后台保存不会切换当前条目或抢回焦点。连接切换使旧会话及其回执失效，A→B→A 也不能接收第一代 A 的回执。Redis DB 和 SQL schema 属于执行目标，改变它们只取消旧执行，不能丢弃经验保存回执或解除保存锁。列表、筛选及审批刷新仅更新列表。

SQL 未缓存条目读取期间，元数据和执行区禁用；失败可重新读取。加载响应同时检查连接身份、请求序号、条目和草稿身份。显式重载前将有修改或执行记录的原稿保留到恢复入口，新加载草稿不携带旧结果；失败、重试和切换不删除原稿。恢复后的草稿带回原内容、执行事实和基线，继续执行原版本冲突检查。干净的已执行稿显示“恢复草稿与执行结果”，有未保存修改的稿显示“恢复未保存草稿”；重复恢复不产生同 token 的重复项。

Redis/Kafka 同样提供显式重载、错误重试及草稿恢复；重载响应仍归属于原条目，切换选择不会让它覆盖当前编辑器。

SQL 初始打开、连接身份重置及显式新建共用草稿登记入口，在编辑和执行前建立 `__draft__` 绑定。四源执行共用独立的执行票据和目标生命周期，按原草稿 token 接收进度与终态，不以编辑修订、当前选择或条目绑定判断执行事实是否有效。执行期间可以修改正文及元数据；后台回执只更新原稿，不推进保存基线、不覆盖输入、不抢焦点。新建及重载替换绑定时，在途原稿进入恢复入口，完成后仍可查看自己的回执。

结果区保留发起时的正文和实际派发内容，SQL 选区和解释记录实际派发 SQL。正文改变时提示“结果来自修改前的内容”，仅改元数据不提示正文变化。每稿仅展示最近一次执行；Redis/Kafka 结果与错误随草稿保存，可信的 Kafka 部分回执和 unknown 同时展示。SQL 停止后保留已确认成功/结果未知/未执行事实，迟到成功不能恢复为成功。连接、重连、DB/schema 改变先使执行票据失效，再取消请求并清空执行结果，旧执行不能覆盖或解除新执行的忙碌状态。

命令正文编辑器在加载及读取失败时通过共享编辑器实际设为只读，加载成功后恢复编辑；执行和保存的忙碌状态不会禁用编辑。

## 入口与规则对应

| 入口 | 共同规则 | 回归入口 |
|---|---|---|
| 四源新建、保存、切换、恢复 | DraftSessions、editDraft、acceptDraft；连接世代与请求归属 | knowledge-draft-session、knowledge-async-ui |
| SQL 相似合并、新版本、变体、自动去重回执 | 同一回执入口，真实 ID，逐字段修订，独立目标草稿 | knowledge-async-ui、knowledge-lineage |
| 列表、相似分析、计数、分组、去重 | latestPublishedByFamily 从完整历史选择可写链头 | knowledge-archive-lineage、sql-templates |
| 普通发布、注释整理、审批正文更新 | isWritableLineageHead；提交前连接、版本和快照校验 | knowledge-lineage、knowledge-concurrency、knowledge-tidy |
| 普通删除、重复项归档、审批归档 | 整链归档、链头校验、一次持久化提交 | knowledge-archive-lineage、knowledge-tidy |
| 执行、连接切换、DB/schema 切换 | 执行作用域独立，旧结果失效，保存锁不被旧请求释放 | knowledge-async-ui、sql-workspace |

## 验证入口

- `npm run check`：类型检查、全部单元/协议测试和构建。
- `npm run test:package-closure`：运行依赖闭包。
- `npm run test:knowledge-async-ui`：真实 Hook、生产经验库组件及实际 Host 存储，经本地 HTTP 验证延迟响应、继续编辑、外部审批、草稿归属、加载、变体发布和整链归档。连接和执行 DB 由验收夹具提供，命令正文编辑器为测试输入框，不代表真实数据库执行或生产 Redis 目录树验收。
- `npm run test:knowledge-execution-ui`：生产 SQL Hook、编辑器、运行/停止按钮及结果控件，验证初始草稿、连接重置、失败/部分回执、停止、迟到成功、执行目标切换及后台结果归属；知识读写使用实际 Host，SQL 执行 bridge 为受控实现。
- `npm run test:knowledge-owner-ui`：四源生产编辑器、回执控件和真实 Hook；覆盖执行中编辑/撤回、恢复、停止、连接/目标往返、重入、实际 HTTP 解析后的部分回执、审批刷新及加载只读。包含 `knowledge-terminal-retention-ui-acceptance.mjs` 的终态后审批/重选、主动重载恢复、保存基线与目标清理检查。知识存储为实际 Host，执行返回受控。
- `npm run test:knowledge-concurrency-ui`：陈旧草稿、筛选、整理审批、重载和页签恢复。
- `npm run test:sql-workspace`：生产 SQL 工作区、执行会话、变体和宽窄窗口交互；其 bridge 为受控实现。

这些验证不等同于真实数据库、Kafka/Redis 服务、模型链或安装后 Desktop 的验收。
